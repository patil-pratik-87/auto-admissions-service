How each option works

ARules engine
the model extracts typed facts; code makes the decision
once per policy release Leitfaden → rule authoring + human review → versioned YAML rules → per application applicant PDFs → extract factsmodel call → typed facts + page refs → rules evaluatorcode → ApplicationResult
BFull policy workflow
nothing prepared in advance — the whole handbook rides along on every run
per application · nothing cached Leitfaden →93.5k tok policy_analystderives criteria →criteria JSON decision_maker+ applicant PDFs → ApplicationResult
CAgentic RAG · TOC navigation
compiles criteria once from whole sections, then loops evaluator ⇄ critic
once, then cached Leitfaden → agent reads sections by heading → compiled criteria cache →~3.1k tok per application applicant PDFs → evaluate ⇄≤1 retry criticnever sees the PDFs → ApplicationResult
DAgentic RAG · vector retrieval
same graph as C; finds policy text by meaning instead of layout
once, then cached Leitfaden → vector indextext-embedding-3-large → agent retrieves top passages → compiled criteria cache →~2.8k tok per application applicant PDFs → evaluate ⇄≤1 retry criticnever sees the PDFs → ApplicationResult
colored border = model call · dashed = cached artifact · plain = document or code · ⇄ = the critic can demand at most one retry option B's optional critic (ENABLE_CRITIC) was off for this experiment · full C/D spec: experiment/admissions-agentic-rag/SPEC.md
